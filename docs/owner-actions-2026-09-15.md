# 운영자가 직접 해야 할 일 (2026-09-15 기준)

코드 작업으로는 대신할 수 없어서 남겨 둔 일 세 가지다. 끝낸 항목은 이 문서에서 지우거나 완료 날짜를 적는다.

## 1. GA4 측정 ID 넣기 — 아직 안 됨

> 참고(2026-09-15): 쿠키 없는 기본 방문 집계는 Cloudflare Web Analytics로 이미 켜졌다(대시보드 Workers & Pages → lowstamp → Metrics, 비콘 부착 확인). GA4는 재방문, 찜, 스팀 이동 같은 행동까지 보고 싶을 때 넣으면 된다.

방문 분석 코드(`web/src/lib/analytics.js`)는 배포돼 있지만 측정 ID가 비어 있어서 **수집이 꺼진 상태**다.
ID가 비어 있으면 빌드할 때 수집 코드 자체가 빠진다(2026-09-15 라이브 번들로 확인).
캘린더 알림 버튼 클릭(`calendar_add`)과 가이드 안 버튼 클릭(`guide_cta_click`)도 기록되게 만들어 뒀지만,
ID가 들어가야 실제로 쌓인다.

넣는 방법은 둘 중 하나다.

- analytics.google.com 에서 GA4 속성을 만들고 웹 스트림(lowstamp.com)을 추가해 `G-`로 시작하는 측정 ID를 받는다.
- 그 값을 Cloudflare Pages → 설정 → 환경 변수에 `VITE_GA_MEASUREMENT_ID` 로 넣고 다시 배포한다.
  (또는 값을 알려주면 코드에 넣어 커밋해도 된다. 측정 ID는 페이지 소스에 보이는 공개값이다.)
- 켜진 뒤 GA4 관리 → 제품 링크에서 Search Console 을 연결한다.

## 2. 네이버 블로그 원고 두 편 올리기 — 완료(2026-09-16)

> 2026-09-16 완료: 운영자 계정으로 가을 세일 글을 먼저, 이어서 가족 공유 글을 발행했다. 발행 전에 전체공개와 검색 허용을 확인하도록 안내했다. 원고는 제목, 본문, 태그 순으로 한 조각씩 복사해 붙여넣었다. 네이버 태그 칸은 여러 개를 한 번에 붙여넣으면 등록되지 않아서 하나씩 입력했다. 효과는 며칠 뒤 네이버 검색 노출과 Cloudflare 방문 분석의 blog.naver.com 유입으로 확인한다.

가족 공유 정리, 2026 가을 세일 기간 정리 두 편. 원고는 대화에서 파일로 전달했고 **이 저장소에는 넣지 않았다**.
둘 다 "제가 운영하는 사이트"라고 밝혀 뒀고, 광고성 글로 보이지 않게 정보를 먼저 주고 링크는 뒤에 뒀다.
블로그·카페 게시는 운영자 계정으로 직접 해야 한다.

> 2026-09-15 추가: 운영자가 처음 원고 파일을 찾지 못해 두 편을 다시 썼다. 사이트 가이드와 문장이 겹치지 않게 새로 썼고(네이버 유사 문서 판정 회피), 제목·본문·태그를 나눠 적었다. 이번에도 저장소 밖 로컬 폴더에 두었다. 게시는 운영자 네이버 계정으로 직접 해야 한다. 2026-09-16 확인: Claude in Chrome 확장은 연결되지만 네이버 블로그 주소는 확장의 안전 제한으로 막혀서 편집기 입력도 대신할 수 없다. 원고를 복사해 붙여넣는 방식으로 올린다.

가을 세일 원고는 **한국 시간 10월 2일(금) 새벽 2시 세일 시작 전에** 올려야 의미가 있다.

## 3. 언어별 주소(`/ko/` 등) — 일부러 보류, 10월 초에 결정

손대지 않았다. 네이버가 한국어 페이지를 막 수집하기 시작한 시점이라, 지금 주소를 바꾸면 네이버가
새 주소를 다시 수집해야 해서 방금 생긴 한국어 노출이 흔들릴 수 있다. 네이버 노출이 자리 잡는지
2~3주 지켜본 뒤 옮기는 순서로 한다.

- **10월 초**에 네이버 서치어드바이저 리포트(콘텐츠 노출/클릭)를 다시 캡처해서 추이를 본다.
- 노출이 유지되거나 늘면: 옛 주소에서 새 주소로 넘겨주는 장치(301 이동)와 `hreflang` 을 함께 넣어 옮긴다.
- 노출이 다시 꺼지면: 원인을 먼저 보고 결정한다.
- 그 전에 바로 진행하길 원하면 결정만 알려주면 된다.
